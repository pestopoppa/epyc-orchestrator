# UTM-B2 verbatim history search

With `trace_navigation_tools` enabled, the owning REPL receives `grep_history` after its first actual context-arm compaction boundary (or a normal session compaction when a verbatim log is present). The tool is absent before that boundary. It reads only the owning task's registered `session.verbatim.md` inode and is exposed through the existing tool budget and broker. The shared registry is not changed. The context-arm conflict guard is unchanged. Existing trace search tools are unaffected.

`grep_history(pattern, context_lines=0, offset=0, count=False, page_size=10)` returns JSON text. Matching is case-insensitive regex, oldest line first; `offset` is a match index, and `next_offset` is null at the end. `page_size` is 1–30 and context is 0–3 lines on each side. Each line is clipped to 300 characters; an oversized first result may be clipped more to guarantee forward progress. A page ends on a complete match record and its serialized response is at most 6,000 characters. `count=True` returns the total and counts by log section (`code`, `output`, `error`, or `header`) without returning matches. Section names follow literal `Code:`, `Output:`, and `Error:` markers in the log; marker-like content can affect attribution. Bad regexes and timeouts are returned as errors; searches use a 10-second deadline.

This is infrastructure only. CF-AB-A7-PROBE also requires the separate CF-AB-A7-SURFACE and UTM-B2-SEARCH-CONTROLS gates, a frozen probe from actual session logs, an eligible served role and a valid binding window. It has not been measured or declared ready here. In particular, access to this tool must be controlled per experimental arm by the probe harness before comparing summary-only with search-enabled arms.

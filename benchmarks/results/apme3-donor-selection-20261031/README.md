# AP-ME-3 donor selection — source validation

Original task: **AP-ME-3 — Complementarity cue for crossover donor selection**, replacing frequency ranking in informed_crossover_candidates. **BSV-3 already computes a semantic conflict severity** over shared subsystem, files touched, prompt sections touched, feature flags and behavior-signature delta. That is a complementarity signal with its sign flipped — crossover donor pairing and BSV-3 conflict scoring **must share one function** rather than be built twice with drifting definitions.

The proposed default-off selection requires both `AUTOPILOT_CROSSOVER_COMPLEMENTARITY_DIAGNOSTICS=1` and `AUTOPILOT_CROSSOVER_DONOR_SELECTION=1`. Kept prompt mutation bytes are recorded only when they match the pre-evaluation served-file digest and the actual target; journal capture requires final eligibility and consumes the transient payload even on refusal. Readers require the current resolved source, exact digest, target and trial identity, existing scope, common observed anchor and sentinel source, and nonempty recorded touched-section and behavior facts. Legacy or incomplete provenance is unknown and cannot produce a donor. Pairs use the unchanged BSV-3 scorer and rank lower conflict first; SafetyGate and BSV acceptance bars are unchanged. At most 30 eligible candidates are paired. Each donor is limited to 4096 UTF-8 bytes; the complete selected contents, trial IDs, source key and hashes together must fit 8192 UTF-8 JSON bytes or no donor text is supplied. This adds raw prompt content to prospective, explicitly enabled journal records; the existing hash-only mutation-context source enrollment needs its scope updated accordingly. It does not backfill existing records or establish optimizer performance.

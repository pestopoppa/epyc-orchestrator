# KPF-26 paired replay scaffold

`kpf26_paired_replay.py` executes an explicitly supplied, digest-pinned executor twice in the manifest's order. The executor is a separate integration boundary: it must run the same frozen tasks against the real scout path, independently read back server flags and identities, capture each child outcome and timing, and record actual checkpoint/fork and interval occupancy witnesses. Its command interface is `EXECUTOR --manifest PATH --arm off|on --evidence PATH`. Stdout/stderr and returned evidence are retained verbatim in a new output directory; interrupted, failed, duplicate, missing or partial evidence is invalid. It does not configure or reload a serving process.

Manifest `epyc.kpf26.paired.v1` pins request and scorer-input files (path and sha256), unique task IDs, sibling count, model, server binary digest, source commit, server argv, executor digest, arm order, a per-arm timeout and a prospective maximum occupancy-sample interval. Evidence must echo those pins and the original manifest digest; both arms must use distinct windows and state the one-skip flag configuration. For every task, executor evidence supplies start/end, occupancy samples spanning the interval, and one record per distinct child with output digest, scored outcome, admission wait, TTFT and prefill tokens. The on arm also supplies one observed trunk/checkpoint witness and a task/slot-bound positive fork witness for each child. Missing or invalid fields produce `INVALID`, never a pass.

`OBSERVATION_COMPLETE` means only that the supplied evidence has the required shape; this scaffold cannot independently authenticate arbitrary executor assertions, and it does not decide the scientific gate. A real executor must bind and retain native server/slot, output, window/grant and sampled occupancy sources and emit the established VB-KVU-PF native records at collection time. Actual flags, binary/DSO provenance, role, cohort, scoring, sampling policy, baseline and non-regression rule must be independently qualified before any run or decision. There is currently no real executor in this change. The test executor is entirely synthetic and cannot satisfy a real gate.
